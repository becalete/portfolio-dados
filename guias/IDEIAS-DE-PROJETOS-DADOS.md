# 💡 Ideias de projetos de ANÁLISE DE DADOS para o seu GitHub

> Aquelas listas de "20 projetos para o GitHub" que circulam no TikTok/Instagram
> (lista de tarefas, clone de rede social, e-commerce, login com JWT...) são para
> quem quer ser **desenvolvedor(a) web**. Não é o seu caso!
> Para quem trabalha com **análise de dados**, os projetos certos são estes aqui. 👇

## ⭐ Não podem faltar (comece por estes)

| # | Projeto | Ferramenta | O que mostra ao recrutador |
|---|---------|-----------|---------------------------|
| 1 | **Análise de vendas** de uma base pública (Kaggle) | Excel ou Python | Que você sabe responder perguntas de negócio |
| 2 | **Dashboard no Power BI** com prints no README | Power BI | Visualização e storytelling |
| 3 | **Automação real do seu trabalho** (versão sem dados da empresa) | Python | Que você resolve problemas de verdade |
| 4 | **Limpeza de dados bagunçados** (antes → depois) | Excel ou Python | Tratamento de dados, o dia a dia da área |
| 5 | **Análise exploratória** com gráficos e conclusões | Python (pandas) | Domínio do básico de Python para dados |

## 🔎 Não tão óbvias (para se destacar)

| # | Projeto | Por que impressiona |
|---|---------|---------------------|
| 6 | Comparar **preços de um produto** em sites diferentes ao longo do tempo | Coleta + análise juntas |
| 7 | Analisar **seus próprios dados** (gastos do mês, treinos, leituras) | Autêntico e rende boa história |
| 8 | Refazer **um gráfico ruim de notícia** de um jeito claro | Senso crítico de visualização |
| 9 | **Excel → Power BI → Python**: o mesmo dashboard nas 3 ferramentas | Mostra a evolução e as 3 habilidades de uma vez |
| 10 | Documentar **um estudo** (curso, livro) com resumos e exercícios | Constância — recrutador vê que você não parou |

## 📌 Regras de ouro

1. **Qualidade > quantidade.** 3 projetos bem explicados valem mais do que 10 vazios.
2. **Todo projeto precisa de um README** dizendo: qual era a pergunta, o que você
   fez e o que descobriu. O recrutador lê o README, quase nunca o código.
3. **Prints valem ouro.** Dashboard sem print no README é dashboard invisível —
   arquivo `.pbix` ninguém abre.
4. **Nunca suba dados da empresa.** Para mostrar automação do trabalho, recrie
   com dados inventados ou públicos.
5. **Conclusão em uma frase.** Todo projeto deve terminar com "descobri que...".
   É isso que diferencia análise de enfeite.

## 🗂️ Onde achar dados gratuitos

- [Kaggle](https://www.kaggle.com/datasets) — milhares de bases prontas
- [dados.gov.br](https://dados.gov.br) — dados públicos do Brasil
- [IBGE](https://www.ibge.gov.br/estatisticas) — estatísticas oficiais
- [Base dos Dados](https://basedosdados.org) — dados brasileiros já organizados
